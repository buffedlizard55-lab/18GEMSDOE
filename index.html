WHY THIS PROJECT EXISTS

A better map starts with a better question.

Fault mapping is a spatial generalization problem, not a hunt for the most convincing-looking raster edge. Every proposal needs a mechanism, a confounder, and a test designed to prove it wrong.

01

Mechanism over resemblance

Prefer physical predictions—such as consistent displacement of multiple shoreline markers—over generic lineament similarity.

02

Spatial tests, not pixel tricks

Freeze basin- or fault-system holdouts before tuning. Report dense and sparse results, controls, and uncertainty.

03

Own the outcome

Keep failed results, provenance, and caveats visible. A closed gate is more honest—and more useful—than a premature upload.

THE RELEASE PATH

Four checks before one upload.

A packaging tool can format a supplied raster; it cannot make predictions or establish scientific validity.

01

Provenance

Verify authorized competition data, source versions, and split hashes.

02

Preregister

Lock a spatial holdout and write candidate predictions before evaluation.

03

Validate

Beat the reproduced comparator, survive controls, and check the official grid.

04

Package & submit

Create a unique TIFF locally, review the note, then upload manually.

CORE VALUES

Maximize P(Win).
Own the Outcome.

Winning means maximizing the probability that a genuinely better, compliant map survives the hidden evaluation—not maximizing the number of speculative submissions. Owning the outcome means exposing uncertainty, keeping the failed tests, and stopping when evidence says stop.
