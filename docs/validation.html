VALIDATION · PREREGISTER BEFORE TUNING

The gate protects the evidence.

Random pixels are not independent spatial tests. The hypothesis must beat a reproduced comparator on withheld basins or fault systems, survive mechanism-specific controls, and retain its provenance.

Current protocol: DRAFT / NOT LOCKED / NO RESULTS. Authorized training data, official template/labels, exact candidate source coverage, and a spatial holdout are absent. Do not tune or report a 18GEMSDOE holdout score yet.

Before any model code

  1. Acquire official competition data through the authorized account; stage raw files outside Git and verify exact bytes/metadata.
  2. Define whole-basin or whole-fault-system blocks. Keep a spatial buffer so related pieces of one structure or marker group do not cross folds.
  3. Freeze the deterministic split polygons/masks, labels/inputs manifest hashes, and preregistration commit before feature engineering or threshold tuning.
  4. Reproduce the H18-3a comparator and its evaluator on exactly that split; if the comparator cannot be reproduced, the candidate cannot pass.
  5. Record predictions before opening the one-time sealed confirmatory slice. Do not use the sealed slice to select features, thresholds, or examples.

Evidence JSON contract

The format tools expect schema version 1, including fields below. Values must come from an executed, reproducible run; do not populate this schema with proposed or fabricated metrics. The repository’s downloadable template is deliberately BLOCKED, and must not be edited to imply a test passed unless all source evidence is present.

Important: the software recomputes means/fold comparisons and checks required flags/hashes. It cannot verify that the underlying label data, holdout mask, control runs, or unique-content audit are honest, authorized, correctly computed, or independent. A reviewer must inspect source artifacts and logs. A `PASS` string alone never establishes a pass.
