Why 0.1563 kept repeating — root cause (three layers)

  1. Same bytes. GEMSDOE1 and 5GEMSDOE host the byte-identical raster (sha 7f00890a62878d61…, payload b966d47c…, 172,974 px at 1.0) — verified live on both sites' build panels this session. 8GEMSDOE differs only on known-fault pixels, which the evaluator masks (forum 11516), so it is the same submission. GEMSDOE2 overlaps it 94.6% (0.1560). Three “independent” 0.1563s are one result counted thrice.
  2. Copied seed. Per the 16GEMSDOE audit, that file sits at 8 paths in 6 repos: each new repo was seeded from earlier evidence folders whose default submission.tif is the old winner. Our convention (unique name + content-id note) exists to make this impossible to do accidentally.
  3. Repeated idea. Near-catalogue top-k predictions were tried in three repos and scored ≤ 0.046 every time (6GEMSDOE 0.0286; GEMSDOE4 0.0343; 10GEMSDOE h16 0.0461). Same idea, new hyperparameters, same ceiling. E1–E5 are new physics, not new settings.

Why 5GEMSDOE == GEMSDOE1 exactly: identical input bytes ⇒ identical DTI. There is no mystery beyond the copy. The fix is procedural (content-id notes, registry Jaccard checks before upload) and is implemented in this repo's submission contract.

What the pattern teaches

  • Proxy scores that reward catalogue resemblance invert on the board (hgb88: best proxy 0.1527 → worst board 0.0286). Our holdout truth must be catalogue-complementary by construction.
  • The group's only score above 0.16 is the 16GEMSDOE topo+geophysics ridge file (0.1855, linkage unverified) — thin ridges + catalogue-complexity prior, i.e. new geometry near known systems. That is convergent evidence for the E1+E2 direction, not proof.
  • Leader gap: 0.3168 − 0.1855 = 0.1313. Under β=0.8 this is a recall gap — unmapped strands we do not emit yet.
