Required GeoTIFF format

Follow the official problem description ↗ and always compare against the exact official sample/template provided by the competition.

  • One raster band, `float32`, GeoTIFF (`.tif`).
  • Exact template dimensions, pixel origin, transform, bounds, projected CRS EPSG:32611, and 100 m cells.
  • Finite prediction/probability values in [0,1] throughout the valid scored footprint.
  • Null/NaN or explicitly masked values outside the valid footprint.
  • The official DTI uses α=0.2, β=0.8 and 300 m support. Passing a format check is not a score prediction.

Command-line validator (format only)

Install Python dependencies, then validate an already-existing candidate file. After downloading a browser-built TIFF, run this Python/rasterio check against the actual official template as an independent format verification. No prediction is created or changed:

python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/validate_submission.py prediction.tif \
  --template sample_submission.tif

# Optional explicit footprint mask
python scripts/validate_submission.py prediction.tif \
  --template sample_submission.tif \
  --footprint valid_footprint_mask.tif

Command-line gated packager

Only use a reviewed passing evidence JSON. The packager copies the official grid, writes a unique float32 GeoTIFF with NaNs outside the valid footprint, reopens it, runs validation, and creates a short note plus JSON manifest under the gitignored build/ directory.

python scripts/package_submission.py \
  --prediction path/to/prediction.tif \
  --template path/to/sample_submission.tif \
  --evidence path/to/passing_holdout_evidence.json \
  --candidate-id H18-N1

# Optional scored-footprint mask if the template has no nodata footprint:
python scripts/package_submission.py \
  --prediction path/to/prediction.tif \
  --template path/to/sample_submission.tif \
  --evidence path/to/passing_holdout_evidence.json \
  --candidate-id H18-N1 \
  --footprint path/to/valid_footprint_mask.tif

Schema and release criteria are documented in the holdout protocol and blocked evidence template. Output is uniquely named using candidate ID, UTC timestamp, content hash, and a random nonce. No file has passed the gate in this checkout.

Manual DrivenData submission steps

  1. Sign in directly to the official competition account and open the GEMS Prize Challenge.
  2. Select Submit → Make new submission (check the live UI labels; no script logs in or uploads for you).
  3. Choose the unique `.tif`. Do not submit research rasters, duplicate artifacts, or unreviewed output.
  4. Paste the generated short note in the platform’s submission note/comment field.
  5. Review the platform receipt/score manually and update registry/score-ledger.csv with date, score, entry/account attribution, and submission ID. Never record a proxy DTI as a live score.
  6. Observe the official limit of three scored submissions per rolling seven days per entity, and the one-final-submission rules. Follow the official rules and staff clarification.

Before any upload

  • Candidate is novel relative to public group work and has a physical mechanism.
  • Spatial holdout, baselines, negative controls, and success/failure decision were fixed before tuning.
  • Candidate beats the reproduced comparator under the registered dense and sparse gate; failed results are preserved.
  • Prediction content and provenance are unique, data are authorized, and no hidden/test labels leaked into features.
  • TIFF was validated against the exact official template; note/hash and output candidate ID match.
  • Submission count and final-entry rules have been checked on the official competition page.
